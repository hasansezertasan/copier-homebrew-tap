# Open a Pull Request for Boilerplate Drift

## Context and Problem Statement

`.gitignore` is generated by Cobo from upstream github/gitignore templates
recorded in `cobo.lock`. `gitignore-drift.yml` used to run `cobo update` and
`cobo check` weekly and fail on drift, leaving a person to regenerate and commit.
Research ([0002](../research/0002-scoop-bucket-template-comparison.md)) found the
sibling Scoop template opens the pull request itself.

## Considered Options

* Report drift only: a failing weekly run, fixed by hand
* Open a pull request with the pinned `hasansezertasan/cobo` action
* Drop the workflow and rely on Renovate and manual `cobo sync`

## Decision Outcome

Chosen option: "Open a pull request with the Cobo action." The job is the only
one in the workflow, with `contents: write` and `pull-requests: write`, and
`fail-on-sync-error: "true"` so an unreachable upstream does not leave a green run
and no pull request. The branch is `chore/sync-cobo-boilerplate` because the
action's default branch name fails `check-branch-name.yml`.

### Consequences

* Good, because drift arrives as a ready-to-review diff.
* Good, because the action is an ordinary pinned digest Renovate maintains.
* Bad, because it adds a write-scoped scheduled job, so the tap's `AGENTS.md`
  least-privilege invariant now lists it.
* Bad, because a pull request opened with `GITHUB_TOKEN` does not start its
  checks; close and reopen it, as with the update pull requests.
